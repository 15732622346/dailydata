# 个人生活记录

把生活记录当作持续维护的时间线：用户随口提供事实时，直接整理并保存；用户询问时，根据最新记录回答。低摩擦执行，不催记、不主动报分，也不为补全非必要信息反复追问。

## 权威文件

工作前读取项目根目录中的：

- `个人生活记录系统规则.md`：所有记录、评分、健康建议、放纵餐和文件拆分规则的权威来源。
- `我的生活记录.json`：已有事实与当天状态。

若 skill 与规则文档不一致，以规则文档为准；不要把规则细则复制到 skill 里。

## 记录流程

1. 识别事件类型：饮食、运动、学习、工作、健康、作息、收支、娱乐或其他。一个事件涉及多个类型时拆为多条关联记录。
2. 未提供时间时使用当前时间。明确区分用户提供的信息与 AI 推测；不确定或未提供的可选字段如实标注，不要编造。
3. 意图清楚就直接写入 `我的生活记录.json`。只有缺少的信息会令记录失真时才提问，每次最多问一个问题。用户说“记录吧”“好的”或“ok”即视为确认。
4. 保存后验证 JSON 有效、记录 ID 不重复、时间戳及字段符合规则；按规则重算当天 `daily_scores`，状态为“进行中”。不要因此向用户追问或主动汇报分数。
5. 用户询问当天评分或状态时，先基于最新记录重算再回答。用户明确说提交或今天结束时，按规则更新当天状态；不要自动提交 Git。

## 记录数据

遵循规则文档定义的记录结构和类型字段。工作记录使用 `content`、`duration`、`output`；学习记录的题量换时长按学习规则执行。缺少食物详情但其他信息足以记录时，标注“未提供”并继续保存，不为此阻塞记录。

每日评分固定为七项：学习、工作、饮食、运动、作息、卫生、自律；评分算法、题量换算、放纵餐处理和状态标记全部以规则文档为准。记录量或规则文档达到拆分条件时，遵循规则文档的文件拆分原则，不要只会追加。

## 写入与安全边界

- 写入前检查 JSON 当前结构，尽量只做必要修改并保留既有记录。
- 用户未明确要求时，不删除或改写历史事实，不补录未提及的事件。
- 健康建议遵循规则文档及其中的个人注意事项；不自行调整药物。涉及高风险健康问题时建议寻求专业医疗帮助。
- 只在用户明确要求时执行 Git 提交；不自动联系外部服务。
